# Quickstart: Validate ES Futures Daily Ingestion

Validates the feature end-to-end per the contracts in `contracts/` and the data
model in `data-model.md`. Does not include implementation code — see `tasks.md`
(generated by `/speckit-tasks`) for build steps.

## Prerequisites

- Python 3.12 environment with project dependencies installed.
- A Polygon.io API key with futures data entitlement, available as the
  `POLYGON_API_KEY` environment variable (or, in deployed environments, in AWS
  Secrets Manager per research.md item 10).
- AWS credentials with write access to the target raw S3 bucket, available via the
  standard AWS credential chain (env vars, `~/.aws/credentials`, or an assumed
  role).
- Target S3 bucket name available as the `RAW_BUCKET_NAME` environment variable.

## Scenario 1 — Single-day ingestion (User Story 1)

1. Pick a known past trading date with published Polygon.io ES data, e.g.
   `2026-08-25`.
2. Run the backfill CLI for that single date:
   ```text
   ingest-es-futures backfill --start-date 2026-08-25
   ```
3. **Expected outcome**:
   - Exit code `0`.
   - Exactly one `RawDailyBar` object exists at
     `s3://$RAW_BUCKET_NAME/raw/polygon/es_futures/daily/contract=<resolved-ticker>/date=2026-08-25/ingested_at=.../bar.json`,
     conforming to `contracts/raw-daily-bar.schema.json`.
   - An `IngestionRunRecord` printed to stdout (and written to S3) shows
     `outcome_by_date: {"2026-08-25": "success"}`.
4. Re-run the identical command.
   **Expected outcome**: exit code `0`; no new `RawDailyBar` object is created
   (idempotent re-run, FR-006) since the fetched value is unchanged.

## Scenario 2 — Non-trading day handling (Edge Case)

1. Run the backfill CLI for a known market holiday or weekend date, e.g. a
   Saturday.
2. **Expected outcome**: exit code `0`; `IngestionRunRecord.outcome_by_date` shows
   `"skipped_non_trading_day"` for that date; no `RawDailyBar` object is written.

## Scenario 3 — Contract roll across a range (User Story 2)

1. Run the backfill CLI with `--start-date` / `--end-date` spanning a known
   historical ES quarterly expiration (e.g. a range crossing a December
   expiration).
2. **Expected outcome**: exit code `0`; the `RawDailyBar` objects written before the
   roll date carry the prior quarter's `contract_ticker`, and those on/after the
   roll date carry the new quarter's `contract_ticker`, per
   `data-model.md#ContractRollSchedule`.

## Scenario 4 — Source not yet published (Edge Case)

1. Invoke the daily job (or backfill CLI) for the current trading date before
   Polygon.io's expected end-of-day finalization time.
2. **Expected outcome**: non-zero exit / raised error; no `RawDailyBar` object is
   written for that date; `IngestionRunRecord.outcome_by_date` shows `"failed"` with
   an explanatory `error_detail` entry.

## Scenario 5 — Scheduled daily run (User Story 1, deployed)

1. Deploy the Lambda + EventBridge Scheduler stack (per `contracts/daily-job.md`)
   to a non-production AWS account/stage.
2. Wait for (or manually invoke) the scheduled execution.
3. **Expected outcome**: same as Scenario 1, produced without manual invocation,
   and a CloudWatch Alarm exists that would fire on a Lambda invocation error (per
   `contracts/daily-job.md`'s failure-signaling requirement).

## Scenario 6 — Ambiguous contract determination (Edge Case)

1. Construct a case where the locally computed front-month ticker for a date
   disagrees with Polygon.io's contract reference data for that date (e.g. via a
   mocked reference response in a test double).
2. **Expected outcome**: non-zero exit / raised error; no `RawDailyBar` object is
   written for that date; the date is flagged for manual review rather than
   guessed, per FR-010.
